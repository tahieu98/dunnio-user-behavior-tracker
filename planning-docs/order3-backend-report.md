## API and transaction decisions

- Collector validates consent, v1 schema, UUID, 1–100 entries, integer counts 1–10000, timestamps in the last 24 hours with at most 5 minutes future skew, explicit context dimensions, allowed paths, anchors/rectangles and pointer planes. The shared global / test JSON parser enforces 64 KiB. Collector uses the existing site origin alias comparison and tracked-page authorization; `all-public` page registration runs inside the ingest transaction. `siteKey` is public, not a dashboard credential. Dashboard reuses existing JWT authentication and the existing success/data envelope.
- Canonical SHA-256 sorts JSON object keys recursively, retains entry order, and hashes the complete received JSON including ignored extras. Unknown text/URL/person fields are never stored in counters. Same site + batch ID + changed payload returns 409.
- Receipt upsert, locked SHA check, registration authorization and all counters share one transaction. A random `claim_token` distinguishes this transaction's inserted receipt from an existing receipt without depending on mysql affected-row flags. A no-op `INSERT ... ON DUPLICATE KEY UPDATE` obtains the exclusive receipt lock before SHA checking. Initial duplicate-INSERT/shared-lock code failed the real 12-concurrent-retry test; the exclusive claim fixes this. Deadlocks / lock timeouts retry the full transaction up to twice.
- UTC+07 `event_date` records the measurement day. Reporting validates real 2000–2099 ISO calendar dates, inclusive end dates, 1–366 days, 1–12 unique period IDs, labels/groups and nonoverlap. Optional `period.version` / `period.width` overrides are validated; root defaults remain supported.
- Reports hold one repeatable-read InnoDB transaction across all periods, counters and snapshots, preventing a concurrent ingest from appearing in the numerator but not its denominator. Stored BIGINT counts and grouped totals must fit `Number.MAX_SAFE_INTEGER`; oversized JSON counts return 422 instead of silently rounding.
- Reports preserve exact sampling metadata as a distinct sorted `sampleRates` array per period and warn when sampled data occurs. Rates divide received taps by received pageviews; no extrapolation or unique-user claim occurs. Six-decimal sampleRate validation avoids floating-point multiplication rejecting valid decimal rates.
- Points are 20px buckets split at original 12-column / 50px grid-cell boundaries. Representative coordinates use the midpoint of bucket ∩ cell ∩ declared plane, so a tap at y49 never moves into row2. `fixed` points retain viewport geometry and do not contribute to document-grid cells. The v1 context has no documentWidth, so horizontal overflow x ≥ viewportWidth is explicitly rejected rather than silently clipped into column12. `unmarked` region does not create another element.
- Relative element bins are 0–19; counters keep weighted position sums, original element key/quality/region, plane/pointer, and min/max bounding rectangles. Centroids therefore use tap counts as weights.
- Comparisons sum counts and pageview denominators across each group, use B−A, and use A as percentage baseline. A=0 percentage is null. A missing constituent period makes its group missing, whereas pageviews with no taps are real zero. Incompatible version, width, document height, or viewport geometry suppress cells / positional comparison. Explicit-key count totals remain available across layouts; structural-key totals across incompatible layouts become null with warning. Elements spanning document and fixed planes do not receive a combined positional claim. Snapshot overlays require matching site/path/device/version/width and one matching observed document height. Truncated points are marked at 10000 per period; cells and summary use all rows.

## Archive SQL interface

All tables use InnoDB and site foreign keys. Daily table primary keys are `(site_id,event_date,dimension_hash)`; `dimension_hash` is lowercase ASCII hex SHA256. It deliberately excludes site_id, allowing site ID remapping on restore without recomputing the digest. Save and restore every visible geometry/sampling field, not just the hash. Decimal SQL values may arrive as strings; preserving them is lossless.

- `touch_batches`: site_id, batch_id, payload_sha256, claim_token, sample_rate, entry_count, pageviews, taps, received_at. Receipts must remain at least 72 hours. Expired production timestamps are rejected before receipt lookup. Parent archives aggregates rather than receipts.
- Daily shared fields: event_date, page_path, device, layout_version, viewport_width, viewport_height, document_height, sample_rate. `touch_daily_pages` adds pageviews/taps/first_seen/last_seen; datetime values are UTC and DATE is the UTC+07 day.
- `touch_daily_points` adds element_key, region_key, anchor_quality, fixed(0/1), pointer_type, x_bucket, y_bucket, grid_col, grid_row, count.
- `touch_daily_elements` adds element_key, region_key, anchor_quality, fixed(0/1), pointer_type, u_bin, v_bin, count, sum_x, sum_y, min_x, min_y, max_x, max_y. Count sums use BIGINT UNSIGNED, position sums DECIMAL(30,4), bounds DECIMAL(14,4), sample_rate DECIMAL(8,6).

`touchMath.hash(value)` exports the canonical hashing helper. `touchStore.aggregate(batch)` exports the exact archive-ready row construction. Pages hash only the daily shared fields; points hash shared fields plus the listed anchor/plane/pointer/bucket/grid fields; elements hash shared fields plus anchor/plane/pointer/u_bin/v_bin. Mutable counts/sums/bounds/timestamps are excluded from dimension_hash.
